# 踏んだエラーと、そこから決めたこと

maku と t8lab で実際に起きた不具合・手戻りを、次に同じことをしないための決まりにしたもの。
チップそのものの癖（浮動小数点なし、64 ビット除算なし、ROM に見える定数、音声割り込みの予算）は [RULES.md](RULES.md) にあり、ビルドが検査する。ここはその外側。

書き方：**何が起きたか** → **決まり**。括弧は出どころ（リポジトリとコミット・decisions.md の日付）。

## 画面

1. **つまみを回すたびに画面全体が点滅した。** 操作のハンドラが全画面の描き直し（`ui.force`）を立て、黒で塗ってから描いていた。ボリュームノブでフォーカスを移したときにも同じ（maku fa19873、4ffebe6）。
   → 操作で全画面を描き直さない。区画は不透明に塗り直すので、署名の変化だけで足りる。テスト「回しても全画面が塗られない」で固定。
2. **ボリュームノブを回すと、別のつまみの値が光った。** ハイライトの判定が、音量つまみの列番号とマクロの番号を比べていた（maku 3eafae6）。
   → ハイライトは、それを起こした操作子の種類と番号で判定する。種類の違う番号同士を比べない。
3. **新しい表示を足したのに画面が更新されなかった。** 署名に値を足し忘れた（maku UI_RULES 6）。
   → 新しい表示 = 署名に1つ足す、をチェックリストに入れる。
4. **GREY パレットでトラック色が灰色になった。** パレット用の混色 `ux_mix` は明るさで灰色にする（maku `mk_mix`）。
   → トラック色は RGB チャネルごとに混ぜる専用の関数を使う。
5. **文字の中央が最大 1.5px ずれた。** 送り幅で揃えていた。
   → インクの外接で揃える（`ink_in`）。端数は左・上へ。文字間のずれはテストで落とす。

## 時間と数

6. **電池の通知が出たり出なかったりした。** `since = fm1_ms | 1`（0 を「未設定」にするため）としたうえで `fm1_ms - since` を符号なしで比べ、`fm1_ms` が偶数のとき負になって巨大な値に回っていた（maku 2026-10-11、BATTERY のテストが捕まえた）。
   → 時刻の差は符号付きで比べる（`(int32_t)(now - since) >= d`）。「未設定」を時刻の値に混ぜない。

## 保存とフラッシュ

7. **REC を押すと音が約 40 ms 途切れる。** 4 KiB の消去は割り込み禁止で、音声も XIP の読み出しも止まる（maku 2026-10-11）。
   → 消去は SOFT ゲインで包む（`MANNER:erase-dip`）。さらに、人が聞いていない時に先に消しておく（`MANNER:rec-preerase`）。[UI.md](UI.md) 9。
8. **保存したものが、表の並び替えで別物を指しうる。** パレット・音色カタログ・いいねが番号で参照していた（maku 2026-10-11）。
   → 保存から参照される表は追記のみ。行には固定の id を持たせ、保存は id で持つ。変えた行は新しい id の新しい行、やめた行は重み 0 で残す。
9. **古い・壊れた保存の読み込み。**
   → 長さ・マジック・版・チェックサムが合わなければ空から始める。知らない id・範囲外の値の項目だけ読み飛ばす（RAM で詰め、書き戻すのは次の保存時）。ダウングレードで失うのは再生できないものだけ（maku 2026-10-11）。
10. **どの領域がアップデートで消えるかを知らずに置き場を選びかけた。**
    → 置き場を決めるときに「何で消えるか」を decisions.md に書く。maku の読み：Felucca ローダはアプリ領域 `0x4000..0x93000` だけを書く、OTA ステージングは `0xE0000..0xE4FFF`、`0xE5000..` は公式への復帰（Return to official V15）で消える。コードから読んだもので、実機では未確認。

## 音とボイス

11. **8 ボイスが足りなくなり、パート同士が音を奪い合った**（120 世界中 16〜73 で発生、maku 2026-10-10）。
    → パートごとにボイスの持ち分を決める（`maku_voice_cap`）。数え方にも注意：「8 ボイス使用中に note-on」はパートが自分の音を置き換えるのも数える。他パートからの奪取（`voice_kills`）で数える。
12. **ある機能を足したら、既存の音が変わっていないか分からなくなる。**
    → 機能が OFF のときの出力は1ビットも変えない。乗算は OFF で ×1.0 ちょうどにし、ゴールデンのレンダリングで確かめる（maku 2026-10-09 ダッキング）。
13. **ある音色が全スケールで怖く聞こえた。** マクロが粒ごとのランダムなデチューン（±3〜7 半音）を動かしていて、スケールの外に出ていた（maku 2026-10-11 Pitch levels）。
    → 「外れない」は音程だけでなく、ピッチの揺れにも当てはめる。揺れの幅は世界ごとの段（STILL / SWAY / WARP）で上限を決める。

## ビルドと CI

14. **実機向けのビルドが、気づかないうちに通らなくなっていた。** エディタを外したあと、`size_fns.py` が消えたファイルを読もうとして止まり、予算表（`target_budget.txt`）も古いまま検査できなくなっていた（maku 2026-10-10）。
    → 実機向けビルドは毎回の変更で通す（ツールチェーンのある環境で）。ファイルを消したら、ツール側の参照も同時に消す。
15. **エミュレーターのビルドが壊れて、マージを取り消した。** ファームにだけある宣言（`FL_JEDEC_OK`、`FM1_OCT_BOTH`）を共通コードが使い、エミュレーター側に定義がなかった（maku 1c2312a、PR #3 の revert）。
    → ハードの宣言を共通コードから使うときは、ホスト / エミュレーターの側にも同じ名前を置く。PR の CI でエミュレーターのビルドを回す。

## エミュレーターとコアの分け方

16. **エミュレーターを先に作ったら、別の画面になった。** t8lab の最初の版は新しいページと独自の画面で、MAKU の見た目から外れた（t8lab 2026-10-11）。
    → エミュレーターは実機と同じ描画を使う。JS で描くなら、C の描画の写しとして作り、レイアウト・フォント・色を変えない。
17. **JS のコアと C のコアがずれうる。** 
    → 同じ操作の台本を両方で再生し、イベントと状態を突き合わせる（t8lab `tests/t8_parity.sh`）。機能は両方のコアに同時に入れる。浮動小数点で書いた実験（`T8_REAL`）は、実機の整数版と一致するか別に確かめる（未確認）。
18. **重い数学関数をサンプルごとに呼んでいた**（t8lab キックの `Math.tan` / `Math.pow`、M6 の計測）。
    → C に移すときは近似かテーブルにする。CPU は移植前にブロックあたりで測り、予算と比べる。

## 文書

19. **仕様書と実装がずれた。** 経緯と現状が同じ文書に混ざり、古い記述（SINK の時間など）が残った（maku 2026-10-11）。
    → 仕様書は「いまのコードがすること」だけ。経緯は decisions.md へ。コメントの古さも直すときに一緒に直す。
20. **「どこでも使えない組み合わせ」を後から知った。** OCT− + OCT+ はパネル設定と 5 秒長押しの UBOOT に使用済み（t8lab MODES.md）。
    → 予約済みの操作は [HARVEST.md](HARVEST.md) の表に集めておく。
