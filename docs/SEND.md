# SEND: 手元の音源データを FM-1 とエミュレータへ送る web ツール（仕様）

**状態: 仕様の草案（コードはまだ無い）。実機で確かめたことは何も無い。** niwa の共有物（`web/send/` と、ファーム側の読み出し
`firmware/src/send.h`）にする。chip で出た草案（`docs/SEND.md`、chip の branch `claude/send-tool-design`）と、tai の要件（tai の
`docs/SPEC.md` と本人の回答）を 1 つにまとめた。tai の人は「**tai への確認**」の節に答えてほしい。

## 何のためか

各自が手元で作った音源データ（rip した曲、サンプル）を、**自分の端末の中だけで**整えて、次のどちらかへ送る。UI は 1 つ。

- **エミュレータ**（ページ内のプレイヤー）— 実機なしで試せる。
- **FM-1 実機**（Web MIDI の SysEx）— 本体のフラッシュに保存する。

## 守ること

1. **データはブラウザの外へ出さない。** アップロードも、サーバ保存も、repo への追加もしない（他者の音楽から作られた物があり得る）。
2. **niwa にプロジェクトの名前や仕様を書かない。** プロジェクトが上書きする差し込み口にする（下）。
3. **実機で確かめていないことは、確かめていないと書く。** 実機側（フェーズ 2）はこの環境では確かめられない。
4. エミュレータと実機で、**同じブロブを同じ場所に置き、ファームは同じ読み方をする。** 差を作らない。

## 用語

- **ブロブ**: 1 件のデータ（曲 1 つ、サンプル 1 つ）の入れ物。下の「ブロブ」。
- **領域**: フラッシュの中の、この仕組みが使う連続した範囲。
- **ディレクトリ**: 領域の先頭にある、ブロブの一覧。

## フラッシュの領域

フラッシュは 1 MiB。更新用のステージング `0xE0000..0xE4FFF`（`ota.c`）と設定 `0xFC000` は**使わない**。

| 領域 | 範囲 | 大きさ |
| --- | --- | --- |
| A | `0x97000..0xDFFFF` | 292 KB（73 セクタ） |
| B | `0xE5000..0xFBFFF` | 92 KB（23 セクタ） |

- 1 つのブロブは 1 つの領域に収める（またがない）。
- プロジェクトは自分が使う領域を `SEND_REGIONS` で宣言する（既定は A と B の両方）。複数のファームが同じ機体で別の領域を使うときの
  割り当て表は**まだ無い**（下の「決まっていないこと」）。
- 書いてよい範囲は `FL_RANGE_OK`（`platform.c`）に足す（フェーズ 2）。A は Felucca の主ストア（`FL_DATA_LO..HI`）と同じ範囲なので、
  Felucca 系のファームとは同居できない。

## ブロブ

| バイト | 中身 |
| --- | --- |
| 0..1 | 魔法数（u16 LE。プロジェクトの `SEND_MAGIC`。違えば「このファームの物ではない」） |
| 2 | 版（0） |
| 3 | 種類 `kind` |
| 4 | スロット番号 |
| 5..12 | 名前（ASCII 8 文字、足りない分は空白 0x20） |
| 13..16 | 本体の長さ `len`（u32 LE） |
| 17..17+len-1 | 本体 |
| 末尾 4 | CRC32（u32 LE。0..17+len-1 の全体。多項式 0xEDB88320、初期値・最終 XOR とも 0xFFFFFFFF。`platform.c` の `crc32` と同じ） |

全体の大きさは `21 + len`。1 ブロブの上限は領域の大きさ（ディレクトリの 2 セクタを除く）。

### 種類

| kind | 意味 | 本体 |
| --- | --- | --- |
| 0 | 不明（使わない） | — |
| 1 | 曲 | プロジェクトが決める（niwa は中身を見ない） |
| 2 | PCM サンプル | 下の「PCM サンプル」 |
| 3 | 画像 | 番号だけ確保。必要になった時点で決める |
| 4..127 | niwa 共通の予約 | |
| 128..255 | プロジェクト独自 | プロジェクトが決める |

プロジェクトは `SEND_KINDS` で「どの種類を受けるか」「種類ごとの最大バイト」「中身の検査」を宣言する。受けない種類は黙って捨てず、
ページが「このファームは受けない」と出す。

### PCM サンプル（kind 2）の本体

先頭 16 バイトの見出し、続けて音のデータ。

| バイト | 中身 |
| --- | --- |
| 0..1 | サンプリング周波数 Hz（u16 LE。最大 65535） |
| 2 | 量子化ビット（8 か 16） |
| 3 | フラグ（bit0 = ループする） |
| 4..7 | ループ開始（切り出した後のフレーム番号。u32 LE） |
| 8..11 | ループ終了（同。終了の 1 つ先を指す、半開区間） |
| 12..15 | フレーム数（u32 LE） |
| 16.. | データ。モノラル、符号付き、8 bit は int8、16 bit は int16 LE。**ADPCM ではなく単純な PCM** |

ループしないときも、ループ開始・終了は 0 と フレーム数を入れる。

## ディレクトリ（領域の中の置き方）

> **ここは私（Claude）の提案で、決定ではない。** 細部は実装の前に tai と chip の確認を受ける。

領域は 4 KiB のセクタに分ける。**セクタ 0 と 1 がディレクトリの 2 つの複本**（交互に使う）、セクタ 2 以降がブロブ。ブロブは
連続したセクタに置き、1 件を消すときはそのセクタだけを扱う。

ディレクトリ 1 枚（4096 バイト）:

| バイト | 中身 |
| --- | --- |
| 0..1 | 魔法数（ブロブと同じ） |
| 2 | 版（0） |
| 3 | 件数（0..169。16 + 24×169 = 4072 で、末尾の CRC（4092..4095）に届かない） |
| 4..7 | 通し番号 `seq`（u32 LE。書き換えるたびに 1 増やす） |
| 8..15 | 予約（0） |
| 16 + 24i | 項目 i（24 バイト、下） |
| 4092..4095 | CRC32（0..4091 全体） |

項目（24 バイト）: `0` kind · `1` スロット · `2..9` 名前 · `10..11` 先頭セクタ（領域内の番号、2 以上） · `12..13` セクタ数 ·
`14..17` ブロブの大きさ · `18..21` ブロブ末尾の CRC32 の写し · `22..23` 予約（0）。

- **有効なディレクトリ**: 魔法数・版・件数・CRC が合う物。両方有効なら `seq` が新しい方（`(int32)(a - b) > 0`）。両方無効なら空の領域。
- **同じ (kind, スロット) は 1 件だけ。** 同じ組を送ると置き換える。
- **追加・置き換え・削除の順序**（電源が切れても古い方が残る）: ① 空きセクタ（他の項目が使っていない連続範囲、先頭から順に探す）を
  消して書く → ② 読み返して CRC を確かめる → ③ 新しい内容のディレクトリを、**古い方ではない複本**へ書く。③ が済むまで古い状態が有効。
  置き換えは、新しいブロブを別のセクタに書いてからディレクトリを切り替える（古いセクタは次に使うときに消す）。
- 消去は書く直前に行う（消した物を長く残さない）。同じ場所を繰り返し書かないよう、空き探しは先頭固定でなく、直前の末尾の次から回す
  案もある（フラッシュは約 10 万回の消去で傷む）— **これは未決**。
- 全部消す（工場出荷の状態）= 両方のディレクトリセクタを消す。

## ファームが読む（`firmware/src/send.h`）

起動時、またはブロブが差し替わった旗（下）を見たときに:

```c
/* 0: 見つかり、魔法数と CRC が合った。*body はフラッシュの上の本体を指す（コピーしない）。 */
int send_get(const uint8_t *flash, const send_region_t *r, uint16_t magic, uint8_t kind, uint8_t slot,
             const uint8_t **body, uint32_t *len);
int send_count(...);  /* 一覧（件数と項目） */
```

- `flash` はフラッシュ全体の先頭（エミュレータでは `nor`、実機では XIP の窓）。**実機でフラッシュを直接読めるか（XIP）は確かめていない**
  （コードは `const` がフラッシュから動いているので読めるはずだが、未確認）。読めなければ RAM に写す。
- 無いか壊れていれば非 0。ファームは組み込みの物へ戻る（設定の「保存が無い」と同じ）。
- 純粋な C（`stdint` だけ）で書き、ホストのテストで JS 側が作った領域の中身を読んで確かめる。

## 画面（1 つの UI）

```
[ ファイルをここへ（.wav と、プロジェクトが足した形式。複数可）]
 一覧: 名前 | 種類 | バイト | 状態     ← 行を選ぶと下に詳細
 詳細: WAV = 波形・切り出し・ループ・サンプリング(Hz)・量子化(bit)・試聴・バイト数
 送り先: ( ) エミュレータ  ( ) FM-1 実機 ［接続…］   使用量 ▮▮▮▯▯ 120 / 292 KB（領域ごと）
 [ 送る ]   [ 消す ]   [ 全部消す ]   進み具合・結果
```

- 種類は拡張子と中身で判定。`.wav` は RIFF（PCM 8/16/24/32 bit、float32。モノラル化して扱う）。ほかの形式（chip の曲など）は
  プロジェクトの `SEND_IMPORTERS`（拡張子 → ブロブにする関数）が足す。
- **切り出しとループ点**: 波形を見て、開始・終了とループ開始・終了を決める。ゼロ交差へ吸着できる。ループは試聴で繰り返して確かめ、
  継ぎ目に短いクロスフェードを付けられる。切り出しは量子化の**前**（切ってから縮める）。
- **音質の自動調整**: 種類ごとの最大バイトに入らなければ、`SEND_QUALITY[]`（劣化の少ない順）の段を上から試し、**最初に入る段**を選ぶ。
  既定の段: 44.1 kHz 16 bit → 32 k 16 → 22.05 k 16 → 22.05 k 8 → 16 k 8 → 11.025 k 8 → 8 k 8。選ばれた段と空きを出し、手で変えて
  試聴できる。最低の段でも入らなければ送らず、切り出しを短くするよう促す。
- 送る前に、領域の空き・名前の長さ・種類ごとの上限を確かめ、足りなければ送らない。

## 送り先 1: エミュレータ（フェーズ 1）

- エミュレータの模擬フラッシュ（`web/emu/web_host.c` の `nor`）に、**実機と同じ領域・同じディレクトリ・同じブロブ**を書く。ページは
  変わったセクタを `localStorage` の `store`（`web/emu/app.js`）に保存しており（`worklet.js` の `storeSectors`）、send ページは同じ
  `store` のセクタを書き換える。次にエミュレータを開く（または開き直す）と、ファームが実機と同じ読み方で読む。
- そのために `web_store_areas()` が領域 A・B を含むようにする（`SEND_REGIONS`）。
- 確かめ方: ① ブロブとディレクトリの JS 実装を node で（往復、壊れた物、電源断の途中状態）。② ファーム側の読み出し（C）を、JS が作った
  領域の中身で。③ Playwright（Chromium）でファイルを落として送り、保存されたセクタを確かめる。④ エミュレータの wasm で読めること。

## 送り先 2: FM-1 実機（フェーズ 2。**実機が要る**）

- Web MIDI（SysEx 許可）。Chromium 系のみ、HTTPS が要る。FM-1 は class-compliant の USB-MIDI で見える。
- 今の SysEx は更新用（`ota.c`、`F0 22 24 35 7D F7` = UBOOT）だけで、アプリには届かない。**プラットフォームに「保存」用の SysEx を足す**
  （更新とは別の命令族）。命令は「セクタを消す」「セクタの一部を書く」「ディレクトリを確定する」程度の小さな物にして、順序の責任
  （上の ①②③）はページが持つ。1 回の SysEx は 7 ビット詰めで小さく区切り、区切りごとに本体が ACK/NAK を返す（`ota.c` の作法に合わせる。
  詳細は `ota.c` を読んでから）。
- 消去の間は音が途切れる（約 50 ms/セクタ）。設定の保存と同じ `soft_down_wait()` / `soft_up()` で挟む。書き込み中は転送以外を受けない。
- **再起動なしの差し替え**（tai の希望）: 確定したらプラットフォームが「新しいブロブが有効になった」旗を立て、アプリが `main` のループで
  見て読み出し位置を切り替える（切り替えの間は無音）。旗に気づかないアプリは次の起動で読む。実機で確かめていない。

## プロジェクトごとの使い方（確定済みの要望）

- **chip**: ROM から吸い出した曲（kind 1）を、容量の許す限り複数入れる。
- **tai**: PCM サンプル（kind 2）をスロット 1 つ。再起動なしの差し替えが望ましいが再起動でもよい。音質は自動で下げる。投入時に切り出しと
  ループ点を指定する。複数スロットはいまは要らない。

## tai への確認

1. **標本の最大バイト数**はいくつか。16 bit・44.1 kHz・3 秒は 265 KB で、領域 A（292 KB）にぎりぎり入る。B（92 KB）しか使えない
   場合は 22.05 kHz 16 bit で約 2 秒。tai が使う領域は A・B のどちらか（両方か）。
2. 標本の本体の形（上の PCM サンプル）で足りるか。足りない項目（チャンネル数 2、ルート音の高さ、ゲインなど）は。
3. **フラッシュから直接読めるか（XIP）**を tai の側で確かめられるか。読めなければ RAM に写す前提でよいか（プール 336 KB）。
4. 再起動なしの差し替えで、読み出し位置の切り替えを `main` のループで行う作りで困らないか。
5. 魔法数（`SEND_MAGIC`）、領域、種類の表は tai が決める。決めたら `web/send/config.js` と C 側に書く。

## 決まっていないこと

1. tai の標本の最大バイト数（上の 1）。
2. フラッシュの直読み（XIP）の可否（実機）。
3. 複数のファームが同じ機体で領域を使うときの割り当て表。
4. ディレクトリ形式の細部（上は提案。空き探しの回し方、電源断の扱いの最終形）。
5. 実機側の SysEx の命令の細部。
